# P-009A Local Authentication and Student Session Foundation

## Trust boundary

P-009A removes the local web server's fixed student identity. Every protected HTTP request now reaches `StudentApplication` only after a `StudentSessionAuthenticator` resolves a trusted `AuthenticatedStudentPrincipal`. The browser supplies only an opaque session cookie. Query parameters, route values, form fields, headers, and storage values are never accepted as student identity.

Authentication establishes the student principal; it does not grant resource access. `StudentApplication` continues resolving every attempt and nested student projection by authenticated `studentId` plus attempt ownership. A foreign and nonexistent attempt therefore traverse the same failure path and receive the same bounded unavailable response across application, document, conversation, coaching, meeting, and Results screens.

## Local development adapter

`InMemoryStudentSessionAuthenticator` is a development adapter, not a production identity provider. Its local sign-in page is unavailable when `NODE_ENV=production` and can select only the predefined fictional Student A and Student B profiles. A selection is mapped server-side to an immutable principal and an unpredictable 256-bit token. Only the token is sent to the browser in an `HttpOnly`, `SameSite=Strict`, path-scoped cookie. The principal remains in server memory, expires with the eight-hour cookie lifetime, and cannot be overridden by browser-controlled identity values.

Login replaces an existing local session rather than preserving or accepting its token. Logout revokes the server-side token and expires the cookie. Ordinary navigation and refresh reuse the same authenticated session. Separate cookie jars receive separate principals, attempts, evidence, conversations, coaching, meetings, reports, and history.

## Future provider contract

A future production authentication adapter must implement `StudentSessionAuthenticator.authenticate(request)` and return either a validated `AuthenticatedStudentPrincipal` or `null`. It owns provider token validation, session persistence, expiry, rotation, revocation, and production sign-in/out. The adapter must derive `subject` and `studentId` exclusively from provider-validated server context. It must not accept an asserted student identity from query parameters, routes, form fields, local storage, or ad hoc test headers.

The accounting domain and `StudentApplication` remain provider-independent. Replacing the local adapter must not change attempt ownership, accounting authorization, instructor secrecy, or error-equivalence policy.

## Scope

P-009A adds no signup, billing, administrative identity management, production provider selection, deployment, database-backed session storage, Neon, Vercel, QuickBooks integration, or Booked integration. P-010 remains separate and its draft PR is unchanged.
