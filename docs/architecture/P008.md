# P-008 Client Readiness Report

## Boundary

P-008 is a deterministic presentation layer over the immutable P-006 assessment snapshot and, when present, the P-007 month-end explanation evidence. It does not calculate competency points, alter a readiness classification, or infer new scoring facts. The canonical enum remains stored alongside a student-friendly display label.

No language model is used. A future narrative service may propose wording only after receiving an already-authorized, student-safe projection; its output must cite allowed evidence, pass the same bounded vocabulary and secrecy checks, and may never change points, labels, classifications, or recommended-next-step policy.

## Snapshot and provenance model

`generateReadinessReport` consumes the latest structurally valid assessment snapshot. Every narrative has one or more internal `sourceRefs` that identify assessment evidence or the authoritative snapshot itself. It fails closed when totals disagree, required competencies are absent, references cross attempt/student boundaries, or a report history belongs to another attempt.

Generation creates a deeply frozen, append-only report version. Repeating generation for the same assessment snapshot is idempotent. A later assessment snapshot appends a new report version and preserves the earlier result. A retry is a new attempt and therefore receives a separate report history; it never rewrites the prior attempt.

## Competency interpretation

The report derives only a presentation label from each authoritative competency result:

| Percentage of available points | Label |
| --- | --- |
| 90–100% | Strong |
| 80–89% | Proficient |
| 70–79% | Developing |
| Below 70% | Needs Practice |
| Authoritative status `NOT_ASSESSED` | Not Assessed |

This label does not feed back into scoring or readiness classification. Strengths are emitted only for Strong or Proficient results. Development guidance is emitted for Developing, Needs Practice, or an authoritative help-dependent result. Help is described qualitatively; raw hint counts and scenario-level grading rules are not exposed. Self-correction and corrected critical history remain visible without exposing critical-hook names or answer-key detail.

## Student secrecy and isolation

The student projection deliberately removes provenance IDs, instructor explanations, scenario IDs, solution facts, critical-hook identifiers, scoring rules, and grading metadata. It exposes only bounded narratives, points already awarded, presentation labels, the canonical result, and safe history summaries. Authorized internal callers can retain the immutable source references for audit.

`ReadinessReportService` requires both student and attempt context in its repository lookup. A missing or foreign record returns the same not-found result, preventing client-supplied attempt IDs from bypassing ownership checks or revealing record existence.

## Presentation order

The student view is organized as: report header, overall result and points, five competency sections, strengths, development areas, independence/help, self-correction, critical-risk summary when applicable, communication, month-end explanation, recommended next step, targeted practice, and attempt/report history. It is suitable for a future web or printable view but P-008 intentionally adds neither a production shell nor certificate generation.
