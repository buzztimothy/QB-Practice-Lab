# P-008A Student Bookkeeping Command and Correction Foundation

## Boundary and authority

P-008A adds a domain/application command boundary; it does not add production UI. `StudentBookkeepingCommandApi` takes identity only from the authenticated request and delegates to `StudentBookkeepingCommandService`. The service loads a session through `findForStudent(attemptId, studentId)`, executes one pure aggregate transition, persists the resulting aggregate once, and returns a student-safe projection. A missing or foreign attempt is indistinguishable from a nonexistent one.

The `StudentCommandSession` is the aggregate and concurrency boundary. It owns the mutable P-002 bookkeeping attempt, its evidence/coaching horizon, monotonic revision, immutable audit chronology, and idempotency receipts. Case-template data is never accepted as a mutable command target. Account, entry, payment, invoice, reconciliation, and document references are resolved again inside the owned attempt.

## Ledger and transaction rules

Every financial mutation replaces or removes complete attempt journal entries and validates all resulting entries with the accounting-domain balance invariant before it can return. Compound operations (payment reapplication and the three-part payroll correction) are built in memory and become visible only through the single aggregate save. Failure produces neither a partial ledger mutation nor a success audit event.

Journal lines remain the financial source of truth. Reports, A/R control, undeposited funds, and reconciliation results continue to derive from them. Commands do not store report totals, create plugs, auto-balance, or silently repair entries.

Completed reconciliation fingerprints are immutable accounting history. A supported correction can restore the original reconciled line identity and value, but cannot edit the completed reconciliation. In-progress selections are normalized when lines are replaced or removed. Finish fails closed unless the statement difference is zero and all historical fingerprints remain intact.

## Concurrency, retries, and evidence

Every command requires an expected revision and an idempotency key. A stale revision fails. Replaying the same key with the same command returns the existing result; using that key for a different command fails. Each successful transition records the command ID, revision, target, help level, note, before/after snapshots, and any critical-client-harm hook in the private audit trail. The student projection exposes command IDs and revisions, but not idempotency fingerprints, private before/after evidence, critical hooks, scenario identifiers, template provenance, or instructor data.

Help and self-correction chronology flow into P-006 assessment evidence. A later correction does not erase an earlier critical action. Legitimately unchanged controls use `VERIFY_UNCHANGED`; unresolved ambiguity uses `FLAG_UNRESOLVED` and remains historically visible.

## Evidence horizons

Commands may use only evidence currently visible to the student. The ABC deposit, detailed payroll, and June 24 personal-card resolutions fail closed until their respective client-evidence documents are unlocked. Command errors remain generic and do not disclose the expected accounting treatment or hidden trigger.

## P-009 command map

| Student workflow | Domain command |
| --- | --- |
| Review / mark legitimate | `REVIEW`, `VERIFY_UNCHANGED`, `FLAG_UNRESOLVED` |
| Bank feed match | `MATCH` |
| Categorize / reclassify / transfer | `CATEGORIZE`, `TRANSFER` |
| Exclude / void | `EXCLUDE`, `VOID` |
| Customer payment correction | `REAPPLY_PAYMENT` |
| Known bounded corrections | `CORRECT_OWNER_CONTRIBUTION`, `CORRECT_PRESSURE_WASHER`, `CORRECT_VEHICLE_LOAN`, `CORRECT_PAYROLL`, `CORRECT_CARD_PAYMENT`, `CORRECT_DEPOSIT_TRANSFER` |
| Evidence-gated decisions | `RESOLVE_ABC`, `RESOLVE_PERSONAL_CARD` |
| Historical correction | `RESTORE_HISTORICAL_TRANSACTION` |
| Chart cleanup | `CONSOLIDATE_ACCOUNTS` |
| Reconciliation | `SET_RECONCILIATION_LINE`, `FINISH_RECONCILIATION` |

The map is intentionally framework-neutral so P-009 can bind screens to these commands without moving accounting decisions into components or route handlers.
